# 热力图点击查看当日追番记录 — 实现方案

## Context（背景）

当前首页与公开分享页都有「追番记录热力图」，格子颜色深浅代表当天观看集数，但只有悬浮提示，无法查看某天具体看了哪些动画。用户希望增强：**点击有记录的格子，弹窗显示当天看了哪些动画**（简单文本列表：动画名 + 集数 + 笔记）。要求**登录后首页**与**公开分享页**两处都支持。

**关键现状（已探明，可大幅复用）：**
- 后端 `GET /watch/logs/date?date=yyyy-MM-dd` **已存在**（登录态，WatchLogController.getLogsByDate），返回 `List<WatchLog>`（含 `animeNameCn`/`epStart`/`epEnd`/`epCount`/`notes`），首页可直接复用。
- 分享页是匿名访问，`GET /share/{account}` 返回热力图数据，但**没有**对应的公开「按日查记录」接口，需后端新增。
- 前端热力图组件 `ContributionHeatmap.vue` 目前无点击事件；追番日历页 `WatchCalendar.vue` 已有「点日期→el-dialog 简单文本列表」现成范本。

---

## 方案一：前端弹窗组织 —— 组件内部自带弹窗，注入 `fetchDayLogs` 函数

弹窗 UI 在两处完全一致，收敛在热力图组件内部避免在 Home / ShareProfile 各复制一份；通过 props 注入数据源函数，组件不感知具体接口 URL。不传该 prop 时格子不可点、无弹窗，完全向后兼容。

### 1. `ContributionHeatmap.vue`（组件内）
- 新增 prop：`fetchDayLogs: { type: Function, default: null }`，契约：**返回 Promise，resolve 为已解包的日志数组**（即 `r.data`）。
- 新增内部状态：`dialogVisible / selectedDate / dayLogs / dialogLoading`。
- 格子 `div.heatmap-cell` 加 `@click`：仅当 `cell && cell.count > 0 && props.fetchDayLogs` 时可点；`dialogLoading` 作防连点守卫。
  - 点击后：`selectedDate = cell.date` → `dialogVisible = true`、`dialogLoading = true` → `dayLogs = await props.fetchDayLogs(cell.date)` → catch 置 `[]` → finally 关 loading。
- 组件根节点内追加 `<el-dialog>`：title 为 `${selectedDate} 追番记录`，body `v-loading="dialogLoading"`；列表复用 WatchCalendar 的简单文本结构：`<strong>{{log.animeNameCn}}</strong>` + `E{{log.epStart}}-E{{log.epEnd}} ({{log.epCount}}集)` + `notes`，空则 `<el-empty description="当日暂无记录" />`。
- 样式：可点击格子加 `class="clickable"`，`.heatmap-cell.clickable { cursor: pointer; }`（保留现有 hover 高亮）。

### 2. 父组件注入数据源
- `Home.vue`：`:fetch-day-logs="fetchHomeDayLogs"`，`(date) => getWatchLogsByDate(date).then(r => r.data || [])`（复用 `src/api/watch.js` 已有函数）。
- `ShareProfile.vue`：`:fetch-day-logs="fetchShareDayLogs"`，`(date) => getShareLogsByDate(route.params.account, date).then(r => r.data || [])`。

## 方案二：后端新增公开按日接口（分享页匿名访问）

### 3. `ShareService.java`（接口）
新增签名：`List<WatchLog> getShareLogsByDate(String account, LocalDate date);`

### 4. `ShareServiceImpl.java`（实现）
复用已有 `userMapper.findByAccount` 与 `watchLogService.getLogsByDate`，不动 mapper：
```
User user = userMapper.findByAccount(account);
if (user == null) throw new RuntimeException("用户不存在");
if (!Boolean.TRUE.equals(user.getWatchPublic())) throw new RuntimeException("该用户未公开追番记录");
return watchLogService.getLogsByDate(user.getId(), date);
```
隐私校验与 `getShareProfile` 同一 `watchPublic` 开关，错误风格与 `getPublicCollectionItems` 一致。

### 5. `ShareController.java`（路由）
新增 `@GetMapping("/{account}/logs/date")`，参数 `@RequestParam @DateTimeFormat(pattern="yyyy-MM-dd") LocalDate date`，返回 `Result.success(shareService.getShareLogsByDate(account, date))`。类上已有 `@CrossOrigin`，跨域无需处理。

### 6. `src/api/share.js`（前端 API）
新增：
```
export function getShareLogsByDate(account, date) {
  return request.get(`/share/${account}/logs/date`, { params: { date } })
}
```
request.js `baseURL='/api'`，最终 `/api/share/{account}/logs/date?date=...`，与后端映射一致。

## 关键注意点（坑）
1. **Result 解包层级**：request.js 拦截器返回整个 `Result {code,msg,data}`，组件契约定死"已解包数组"，由父组件在 `.then(r => r.data || [])` 处解包，组件内不再 `.data`。
2. **用户不存在/未公开**：无全局 ExceptionHandler 时抛 500，request.js 会弹 toast 并 reject；组件 catch 置空数组兜底显示 el-empty（与现有 getShareProfile 行为一致，不扩大范围）。
3. **时序/防连点**：用 `dialogLoading` 守卫，catch 先置 `[]` 再 finally 关 loading。
4. **日期格式**：`cell.date` 已是 `yyyy-MM-dd`，与后端 `@DateTimeFormat` 匹配，无需转换。
